- Use Gemini embedding model to embed text to embeddding vectors for the descriptions and query
- Use Numpy to calculate the cosine similarity between the vectors for the descriptions and query
- Use Gemini API to generate an explanation on why the songs were recommended.

## Architecture Overview

The first step of our RAG powered music recommender is the generation of the descriptions for songs. The descriptions of the songs are used to help improve the semantic meaning of what this song is about that aren't obvious from the metadata. And it will be used to help with matching a song from the user's query. For the descriptions, we loop through the song's database and for each song make a prompt to Gemini API gemma-4-31b-it model to generate a description up to 20 words long using the song's metadata. The descriptions are then saved to the song's database.

The next step is the generation of the embedded vectors for each song using it's description. The description is embedded to a vector using Gemini embedded gemini-embedding-001 model with the song's metadata and is saved to a new vector database.

The third step is to firstly get the user's query using Python's input(). And generate the embedded vector for the query. The embedded vector for the query and the embedded vectors for the descriptions are then used to compute the cosine similarity. A cosine similarity close to one means semantically the query matches closely with the song's description. Once all the cosine similarity are computed we then pick the top 5 recommendations. 

The last step is to print out the query and the 5 recommendations songs with explanation. The explanation is generated by prompting the Gemini API again with the help of the query and description in plain text.

## Limitations and Risks

Summarize some limitations of your recommender.

Examples:

- It only works on a tiny catalog
- It does not understand lyrics or language
- It might over favor one genre or mood

You will go deeper on this in your model card.

The system has a bias against users who perfer calm music. If the user has an energy preference of 0.17 or below, then a song can never reach the max potential energy score because the lowest energy song is 0.28 (SpaceWalks Thoughts).

A majority of genres (rock, jazz, indie pop, etc.) have one song. This means if the user preference matches one of those genres, then they have a huge lead in being recommended. They feel like uncontested "winners".

Since genre is being match exactly, then songs with related genres would not be recommended. For an example, if a user likes pop and a song is folk pop then the song would not get points for the genre criteria as it is not exactly "pop". It gets hung up recommending the same handful of songs and has no way for users to widen their exposure to songs in related genres.
